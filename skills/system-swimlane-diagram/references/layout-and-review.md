# 布局与审图指南

## 先排阶段，再放节点

- 按各阶段的真实内容分配列宽。顶部用「编号 + 阶段名」，列间留白，横向铺浅色系统泳道。密集图用不同颜色区分阶段标题，并用对应颜色的细虚线圈整列。检查缩到实际阅读尺寸后，邻列仍分得清。若「同步」和「消费读取」各有一组动作，把它们分列，避免末列过载。
- 框按真实文字留足内边距。框之间和泳道之间预留走线空间。图挤时，先删重复解释或调整列宽，避免把整张图的文字一起缩小。
- 参考风格可以用浅色画布、近白动作框和深色正文。入口用浅蓝，编排用淡黄，存储用浅绿，外部系统用浅陶色，左侧泳道标题与边框同色。用户给了参考图时，以它的配色层次和箭头风格为准，再按当前系统数量和可读性调整。
- 把视觉方式分配给不同含义。**行底色看系统，列标题和外框看阶段，箭头线型看动作。** 行占面积大，优先用低饱和灰调或浅色。相邻行可以同色系，用明显的明暗差区分，也可以用轻微的冷暖差辅助。泳道标签与整行底色配对，行界需要时加一条轻分隔线。
- 让行与列在色相或饱和度上有明显差距。典型搭配是灰调行底配蓝、紫红、琥珀、深绿的阶段色，阶段色集中在标题、外框和需要的节点竖条。预览中相邻行仍分不开时，先拉开明暗差，再视情况加深分隔线。避免用提高所有行背景饱和度的办法强调分行。
- 动作框带左侧色条时，为它指定一个含义。表示阶段时，从所在列的颜色直接取值，确保同列所有框的竖条都与标题、外框同色。含义有变化时，要在图例中说明。纯装饰色条可以去掉。整列虚线外框不带箭头，读取虚线有箭头和数据标签。表名加粗，说明文字保持常规字重。

## 再排箭头

1. 先画从左到右的主线。异步阶段的交接依赖数据库或队列时，画出留下的记录和负责领取的一方。
2. 用直线或直角折线连接具体框边，箭头指向接收方。箭头说明靠近对应线段，避开节点、列边框和其他文字。
3. 两条分支从同一个判断点出发。同一系统负责两条分支时，在它的泳道内排成两条线。双方共用服务时，要标清两条路都调用它，以及分别传入和取回什么。
4. 给相邻的请求和返回各留一条线。用方向和数据名区分「发请求」「拿结果」「回写结果」。知道产出但不清楚接收方或先后时，在产生它的节点标注产出即可。知道某个标识的用途但没证实它存在哪时，把用途标在箭头上。

### 生产与读取并存时

- 默认用**实线**画任务加工、写表和跨存储同步，用**虚线**画消费方从表取数。标明线的含义和数据方向，例如「明细数据 → 页面查询」。如果还要画主动查询请求与返回，分别标「查询条件」和「结果数据」，并在图例说明线型。配置或待核实关系有各自的标签，别与已证实的读取混为一类。
- 同一阶段的竖向连线先对齐起终点。需要跨好几列的共用表或旁路，把线移到专门留出的横向空带，给每条不同用途留各自的通道，再折向目标。禁止用共用线段暗示彼此无关的关系。两条线必然相交时，无交点标记就只表示经过。
- 出图前顺着每条线从头追到尾。交叉多时，优先移动节点、分开走线、把消费节点对齐到各自产出表。画板或文档会重新缩放时，以交付端的实际预览为准，检查虚实线、标题色差、表名字重和标签是否还能辨认。

## 通用示例

导出服务可按「请求导出 → 工作进程领取 → 生成文件 → 返回下载地址」分列，泳道可用应用、API、工作进程、任务库和对象存储。从对象存储返回的箭头标「文件地址」。如果实现里同时保存任务状态和下载地址，在最后一列的数据库小表格里分开写。需要解释领取条件时，把实际状态和时间比较写在「领取」列的小表格里。具体表名和字段从该服务的模型或数据定义核对。

## 出图后逐项检查

| 核对项 | 常见问题 |
| --- | --- |
| 主线 | 后做的动作画在前面，或外部调用还没返回就画成成功。 |
| 分支 | 看不见判断条件，路径中途换了环境，或共用接口看起来只服务其中一条线。 |
| 数据 | 只写「数据库」却没标实际表名。字段没说明读写用途。记录状态被误读成外部操作的成功凭证。 |
| 数据血缘 | 只能看到系统列表，查不到哪张表由哪个任务写入、被哪一方读取。共用表的不同用途被画成同一条线。 |
| 可读性 | 中文被截断，字段顶到下一格，箭头压住动作框或紧贴列边界。正常尺寸和放大尺寸各看一次。 |
| 颜色语义 | 缩到交付尺寸后还能靠明暗分清相邻行，彩色阶段框不会和行底混淆。同列色条与标题一致，文字和箭头在最深的泳道底色上仍清楚。 |
| 修改范围 | 只改画法时改动了已核对的事实，或者把已经移除的案例重新加回图里。 |
