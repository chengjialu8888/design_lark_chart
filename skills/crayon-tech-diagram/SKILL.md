# Crayon Tech Diagram

把技术图重画成统一的白底蜡笔手绘风插图：深石墨色手绘描边，淡蓝/淡绿/淡橙蜡笔填充，手写感大号文字，竖版 3:4。

本 skill 负责画什么、提示词怎么写、怎么验收。实际生图使用宿主可用的图像生成／编辑工具；不把内部工具作为独立包的必装依赖。先读 [可移植调用说明](references/portable-integration.md)。有 `doubao-creative-design` 时读取其当前规则；没有时使用可用的 imagegen／图像编辑能力，或交付提示词与素材清单并注明尚未生成。

## 资源

- `assets/style-reference-zh.jpg`：中文风格锚点图，中文配图默认用它。
- `assets/style-reference-en.png`：英文风格锚点图，来自用户原始提示词包。
- `references/prompt-templates.md`：固定风格段、5 种图型模板、局部修正模板和已踩过的坑。**写提示词前必读。**
- `references/original-prompts.md`：用户原始的英文提示词和 Mermaid 源。做英文图或需要参考约束写法时读。
- `scripts/fetch_and_check.py`：下载生成结果，按真实格式命名，并生成用于审字的缩略图。

## 工作流

### 1. 收集内容源

- 飞书文档：用 `lark-doc` 的 `+fetch` 读取正文。`<img>` 用 `docs +media-download` 下载；`<whiteboard>` 用 `docs +media-download --type whiteboard` 导出缩略图。
- 本地图片或 Mermaid：直接读取。只有文字描述时，先列出节点和连线，再选图型。
- 逐张看清原图里的节点名、连线方向和数值。看不清就放大缩略图重读。

### 2. 为每张图做版式决策

- 用户未指定画幅时优先竖版 3:4，适合手机阅读；按当前工具支持的尺寸请求并核对实际输出，不把某个提供方过去的像素结果当固定保证。用户已选画幅或超宽原图时按任务调整。
- 按内容选图型，模板见 `prompt-templates.md` 第 3 节：
  - 进程或部署关系：容器 + 进程关系
  - 新旧方案对比：上下对比，不用左右分栏
  - 时序图：编号步骤卡片加侧边竖括号，**不画泳道**
  - 规则加数值例子：横向链路 + 进度条
  - 两条路径殊途同归：双列汇合
- 颜色带语义：淡蓝表示中性或容器；淡绿表示新方案、保留、命中；淡橙表示旧方案、问题、外部组件或结果。
- 文字要精简：每个框不超过约 12 个字，全图只允许出现引号内的文字。数值必须和原文一致，不重算、不补造。
- 文字语言跟随文档语言。用户没有指定时，中文文档用中文。

### 3. 写提示词并生成

- 按实际图像工具传入内容参考图与风格锚点，明确两者角色。`image_edit`／`FileBatchUpload` 是一种工具组合，不是所有宿主通用 API；本地路径、附图或上传方式按宿主规则选择。没有内容参考图时只传风格锚点，并按模板改写图号。
- 提示词结构：先放固定风格段；再从上到下逐区描述版面，包括框、颜色、引号内文字、箭头方向和标注；最后加收尾约束。
- 多张图互不依赖且工具支持批量时可批量生成；不假设当前工具存在 `request_list` 参数。

### 4. 验收

1. 运行 `python3 scripts/fetch_and_check.py --out <项目目录>/illustrations <序号-名称>=<url> ...`。
2. 用 Read 逐张查看 `_thumbs/` 里的缩略图，对照提示词核对错字、漏字、多余文字、箭头方向、颜色语义、进度条比例和数值。
3. 有问题时，按 `prompt-templates.md` 第 4 节的模板，用 `image_edit` 只传出错的那张图做局部修正，不整张重画。未修复的图内文字问题必须明确标出；按当前工具规则局部修复，不把有误的图称为已通过验收。
4. 把新踩到的坑追加到 `prompt-templates.md` 第 5 节。

### 5. 回填到文档（如需要）

- 只有用户要求回填时才操作文档；按指定目标新建或替换，保留其他内容。未要求文档操作时只交付图片、提示词和必要说明。
- 飞书文档插图写法：`<img path="@./illustrations/xx.jpg" caption="图 N：一句话说明" width="560"/>`。caption 只写这张图回答了什么问题。
- 原文里的线上截图、指标曲线等真实数据图保持原样，不重画。
