# 图形语法：结构、流程与时间

这里规定“关系怎么表达”，不规定灰纸背景、珊瑚强调或品牌风格。主题另见 [themes.md](themes.md)。

## 选择矩阵

| 读者的问题 | 语法 | 必需材料 | 不要混成 |
| --- | --- | --- | --- |
| 哪些模块组成系统 | 逻辑架构 | 职责、依赖、逻辑边界 | 物理部署事实 |
| 什么运行在哪里 | 部署/包含 | 主机、设备、进程、网络归属 | 目录树或抽象层次 |
| 哪一层负责什么 | 分层 | 层次依据与职责 | 执行先后 |
| 一次任务如何完成 | 流程 | 步骤、条件、输入输出、终止 | 无条件的直线步骤列表 |
| 谁在什么时候交接 | 泳道 | 参与者、动作归属、交接 | 每条线一个相等长度的角色列 |
| 数据经过哪些变换 | 数据流 | 数据对象、处理、存储、消费与权限 | 未说明载荷的组件连接 |
| 谁给谁发了什么消息 | 时序 | 消息、参与者、顺序、返回与分支 | 服务部署图 |
| 一个对象有哪些合法状态 | 状态机 | 状态、事件、守卫、动作、终态 | 多主体对话 |
| 什么结果回到哪里 | 反馈/迭代 | 返回对象、写入内容、触发和退出 | 因为圆形漂亮而硬闭环 |
| 两个版本改变了什么 | 架构差分 | 对象匹配、前后版本、边差异 | 迁移执行时间线 |
| 事件怎样被消费 | 事件轨道 | topic、处理器、消费组、分岔、重试/DLQ | 普通请求强装成 Kafka |
| 为什么这次请求慢 | 拓扑＋trace | 同一观察窗口、测量信号、span、父子关系 | 装饰性 LIVE 仪表盘 |

以上是制作指导，不表示随包存在所有自动生成器。现有资产范围见 [assets.md](assets.md)。

## 流程：分支、合流、并行、回路

1. 活动用动词短语，判断用问题/条件，输入输出用对象名。开始/结束、活动、判断的形状可以辅助识别，文字承担最终含义。
2. 每条判断出线写条件，包括默认/其他路径；不能只靠左右位置猜 Yes/No。分支超过菱形可读容量时用带条件的列表或拆解子决策，不删合法出口。
3. **选择不是并行。** 互斥分支不能画成同时运行；并行分支需要明确 fork，后续需要全部完成时明确 join。若只需任一个完成，写清汇合条件。
4. 合流采用明确汇合节点或端点；两条线交叉不构成合流。优先换位与通道避交叉，跳线仅在该记法允许且图例解释时使用。
5. 回路注明返回哪个状态/步骤、什么被更新、何时退出。重试次数未知就写未知，不默认三次；取消、失败和人工介入按材料保留。
6. 横向换行不改变时序：行尾到下一行行首有明确续接标记。持续监控可没有一次性终点，但必须说明持续运行和停止条件的已知范围。

示例：`提交 → 检查 → [充分] 交付`，`检查 → [缺少必要证据] 补充 → 检查`。示例不意味着所有业务都经过人工确认。

## 泳道与数据流

- 每道代表真实执行主体；一个动作只有一个主要执行归属，协作另用关系表示。可采用“角色 × 阶段”网格；空格保持空，不为了排满补步骤。
- 跨泳道边是交接重点，写清交接物、控制权或请求。权限授予与数据传输分别标记，管理员的配置不等同于替数据工程师执行处理。
- 数据流程可以标输入/输出类型，如原始文件 → 清洗表 → 特征 → 模型输出；编码变化或匿名化需要依据，不能因为模板有转换节点就假定发生。
- 存储节点区分读取与写入；引用/经验输入不等于控制指令；数据副本、队列与缓存有不同语义。
- 在 formal DFD、普通数据管道、责任泳道之间选一套合适记法并说明，不把某一种记法的狭义定义泛化为所有数据流图。

## 时序与状态机

时序图：参与者在上方，生命线向下，消息按时间顺序排列；返回消息与调用分别编码。激活条表达执行区间而非精确耗时，除非有时间尺度。`alt/opt/loop/par` 框表达已知分支/可选/循环/并行；框内标守卫。异步消息和返回不能只用同一种无解释虚线。同步/异步未知则使用普通消息并注明未知，不替系统作协议决定。

状态机：先固定“哪个对象”的生命周期；边写 `事件 [条件] / 动作`，不需要的部分可省。等待、恢复、失败、取消与成功按真实合法转移列出。自循环需有触发事件；“任意状态均可取消”必须确实适用于那些状态，可用范围说明减少重复边，但不能丢掉例外。

## 分层、包含与差分

- 分层的上下关系可能是抽象、技术栈或职责级别，不自动画执行箭头。容器只表示一种明确归属；逻辑模块、进程、GPU、VPC 不混用同一边界。
- 双 GPU 图先核实每张卡上的对象、张量/任务分配、通信方向和同步位置；未给出的 NCCL、NVLink、双模型实例都保留未知。
- 差分使用“之前—变更说明—之后”，相同对象 ID、位置和尺度尽量稳定。新增、移除、属性变化、移动、重新连线分开标识，并用文字/线型辅助颜色。
- 两张快照不证明迁移顺序、停机时间、因果或性能收益。若用户只比较参数，用表格而非两张假拓扑。

## 专业视觉需要专业证据

事件轨道的 topic 是轨道，消费者是真实消费组，分岔必须发生在明确 junction，DLQ 线必须抵达真实死信节点。不能给普通线随意加列车站编号。

运维脉冲需要真实 latency/traffic/errors/saturation 的值、单位、时间窗与状态依据；trace 的父 span 覆盖子 span。历史快照标“快照”，不沿用上游模板的 LIVE 标签。动态频率不代替吞吐或延迟测量。

几何实现与文字计算见 [layout-engineering.md](layout-engineering.md)，可选动效见 [motion.md](motion.md)。
