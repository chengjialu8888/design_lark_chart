# 结构、架构与关系

分层/包含/差分等语法见 [diagram-grammar.md](diagram-grammar.md)，复杂文字和路径计算见 [layout-engineering.md](layout-engineering.md)。

## 先确认主问题

结构图回答“是什么、属于谁、如何关联”。行为顺序是主要信息时读 [behavior.md](behavior.md)，不要把请求时序塞进静态部署图。

识别逻辑模块、进程、设备、部署单元、存储、外部系统和抽象层级。C4 等记法仅在适用或指定时采用；两个 GPU 不意味着两份模型、特定并行方案或特定互联。

节点记录稳定 ID、名称、职责与边界；关系记录起点、终点、类型和必要载荷说明。核心对象与关系关联 [证据](evidence.md)。

## 布局与线条

1. 定主阅读方向与真实边界；并列角色对齐，主链路有视觉优先级。
2. 用完整标签和实际字体安排节点尺寸，预留容器标题和图例空间。
3. 再定节点位置和连线通道。共享侧边分配不同端口，标签与路线不互相遮挡。
4. 包含主要用容器；调用、数据、控制、依赖和反馈用明确图例及标签区分。协议、同步/异步和载荷不得补造。
5. 跨越不等于合流。反馈绕外侧并有返回目标；穿过无关节点应重新绕线，不能只用不透明节点遮住。

正交路线通常易追踪，但径向、环状或专业记法可采用其他路线。风格、主题与字体不决定业务语义。

图例在业务边界外或独立说明区。只有真实职责才增加容器；不用目录层级暗示进程或部署归属。

## 复杂度与保真

不以固定节点数决定删减。根据标签长度、关系密度、实际阅读尺寸选择分组、扩大画布、局部展开或总览加细节。单图要求已锁定时先在范围内重排，必要取舍须说明。

重绘核对核心节点及关键关系的集合，记录合并/折叠/省略。图与图之间共享 ID 或明确对应标签，不用无含义虚线把局部图装饰性地连起来。

## 可选的浏览器检查标记

新建原生 SVG 时可使用以下最小约定，使随包浏览器检查器能测量真实元素。不为旧文件局改迁移整套结构。

```xml
<rect id="gpu-a" data-viz-node="container" x="20" y="20" width="300" height="180"/>
<rect id="encode" data-viz-node="component" data-viz-parent="gpu-a"
      x="50" y="80" width="180" height="70"/>
<text data-viz-owner="encode" x="70" y="120">已核实的模块名称</text>
<polyline data-viz-from="encode" data-viz-to="target" data-viz-kind="data"
          points="230,115 370,115"/>
```

片段仅解释标记，`target` 及样例文字不是可直接交付的完整架构。端点节点在实际图中必须存在。

`data-viz-node` 的值区分 `container` 与 `component`；节点必须有文档内唯一 ID。`data-viz-parent` 表达所属容器，父关系无环；文字可用 `data-viz-owner` 指定所属节点。边使用 `data-viz-from/to/kind`，类型用真实短语，不强制固定枚举。

检查器支持实际 `<rect>` 节点和 `<line>/<polyline>` 边的平移/缩放，不支持旋转节点、曲线路由、非矩形节点的精确碰撞。未标记或不支持的图明确记为覆盖不足，交由适合的工具及目视核验，不得把无告警称为全部通过。
