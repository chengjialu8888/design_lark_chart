# 布局工程：把语义变成可读几何

用于密集图、长标签、复杂边界、中文说明和重绘。参数化布局、文字度量、路径通道与画布预算共同决定可读性。具体像素阈值依画布与阅读尺寸调整，不叠成统一硬门槛。

## 先算文字，再布节点

以目标阅读尺寸确定字体和内容层级：标题、节点名、职责说明、边标签、来源。节点宽度由最长实际行宽与内边距决定；高度由各行真实字高、基线、行距与上下留白决定。不用字符数当精确字宽，CJK、拉丁、公式和字体回退会不同。

设标签的测量宽度为 `label_width`，左右内边距为 `padding_x`，则节点宽至少为 `label_width + 2 × padding_x`；如果多行，分别测量各行。源字号乘显示宽度/画布宽度才是有效字号。例如源文字 24px、画布 1800px、显示 900px 时只有 12px；增加导出像素不会改变这件事。

长标签优先扩大节点、按语义换行或移出次要注释；精确值和术语不能截断成省略号作为唯一信息。标注中保留短位置，完整证据路径放图外。横屏图到手机用局部滚动/分解视图，不把整图强缩。

## 三种可复用布局计算

**阶段 × 角色网格**：`画布宽 = 角色标题列 + 各阶段列宽之和 + 列间距之和 + 两侧边距`。每列宽取该阶段最宽节点/边标签预算；每泳道高取最高节点加标题区和上下通道。相同输入及排序产生相同坐标。

**主路径＋侧栏**：主路径容纳解释所需步骤；侧栏承载真实共享状态、参考或评价对象。侧栏有业务关系才连线，普通说明栏不伪造箭头。公共适配器只在真实共享时置底。大图和局部图用一致 A/B 标记，不用装饰虚线冒充关系。

**环状循环**：站点中心可按 `angle = -90° + index × 360° / count`，`center = hub + radius × (cos(angle), sin(angle))` 计算；根据真实节点边界求进出点。先确认每个环边都是真的；中间只有真实共享状态才放 hub。并非所有回路都需要环形，矩形外侧反馈线往往更易读。

## 路由顺序

1. 容器、标题保留区、节点行列、图例区先就位。
2. 主链路先走；跨层、参考、反馈分配不同通道。不要把线压在容器边线上。
3. 多边共享一侧时分配不同端口；端口避开角和标签，不把多个箭头堆在同一个点。
4. 先选直线/单调折线；折弯太多先改位置。最短路线不是唯一目标，绕过无关节点更重要。
5. 给所有文字留障碍区域，包括容器名、边标签、图例、侧栏、页脚；不是只检查矩形节点。
6. 箭头尖端扣除 marker 的超出量；线从源端到目标端存储，便于方向检查与动画。

路径标签优先垂直偏离线段并贴近明确对象；背景小底板只能解决标注交叠，不用遮住穿节点的错误路径。跨线避免误以为连接：重排、分通道，必要时依专业记法明确桥接。

## 图层与组件

绘制顺序可采用：背景 → 容器 → 连接 → 节点 → 文字 → 图例。它解决遮挡次序，不替代正确几何。光晕、轨道外壳、移动短线均为装饰层，应指向所属边，不能复制出第二条“业务边”。

复制 SVG 组件时同时复制所需 defs 和 style，给 `id`、`aria-labelledby`、marker、clip/mask、节点/边引用加一致前缀。外部 SVG 通过 img 使用时不会继承 HTML 主题变量；要在 SVG 内换值，或转为带前缀的内联 SVG。

## 画布与导出预算

画布包围盒必须覆盖节点、标签、marker、回路、图例及留白。SVG `viewBox`、页面容器、图的最小阅读宽度是三个相关但不同的数：需说明是否发生区域滚动，不照抄来源示例的固定加 48px 公式。

滚动页面的可见区截图不等于完整图导出。独立 SVG 导出看全画布；页面截图保留当时视口与滚动状态。PNG、PDF、浏览器和第三方编辑器对 CSS、foreignObject、滤镜支持不同，目标格式需要实测。

## 验证与覆盖

先核对节点/边集合与来源，再跑 [结构标记](structure.md#可选的浏览器检查标记) 支持的检查。随包工具只覆盖矩形节点及直线/折线，菱形、曲线、旋转和 CSS 裁切不能宣称已完整检查。静态无告警后仍看实际目标尺寸：方向、完整术语、交叉歧义、文字压线、密集区和手机阅读。
