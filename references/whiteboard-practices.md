# 飞书 SVG 与画板兼容技巧

以下为基于公开上游与实际工具的简化适配；特定版本行为必须通过当前转换和实际导出验证。来源见 NOTICE.md。

## 保持可编辑

优先使用 rect、circle、ellipse、line、polyline 和 text；复杂路径、图案、阴影或滤镜可能成为图片或无法保真。曲线路径、渐变等不是“能在浏览器显示”就等于可编辑。SVG 根声明 xmlns、width、height、viewBox。每个标签使用 text，中文长句通过 tspan 明确换行。不要用 foreignObject 承载正文。

SVG 不设置自定义 font-family，适应飞书字体；本地预览中文字体缺失与云端转换是两个问题，分别核验。字号和内边距按内容推导，同层卡片同宽、同基线，连线从边界/锚点出发，不穿正文。

## 箭头

连线使用 line/polyline，带 defs 中的 marker 与 marker-end（必要时 marker-start）。不要把箭头三角形单独拼成 polygon：容易成为图片或与连线脱离。使用前通过一张最小箭头图确认当前工具版本的转换结果。

## 颜色与布局

尽量使用不透明实色；透明度、细描边、文字颜色等在不同导出路径可能表现不同。结构优先，少装饰。不要把原生层级做成整张背景图。看PNG检查布局和裁切；文字颜色有异常时回读 raw 或检查实际页面，不能只凭本地SVG判断。

建议逻辑画布约1600宽起步，但不是固定比例；内容增加时扩展或拆图。几何由网格、节点数、文本行数和间距参数计算，不照抄某张业务图坐标。

## 修复顺序

一次查看后批量列出问题 → 原位局部修SVG → 重新转换/导出 → 查看。优先修文字溢出、连线穿字、重叠与裁切，再调色与装饰。不要每次全量重画导致已通过内容回归。

## 本地到云端

先静态检查，再转换OpenAPI，再按授权范围写画板，最后导出真实飞书图复核。已有画板先保留源数据与token，更新后回读。source.svg、board.openapi.json、feishu.png和检查结果分别保存；没有真实导图时不能声称完成云端视觉验收。
